# Local OCR (no internet, no Tesseract install needed). PINNED, and not loosely:
#   1.2.x/1.3.x load their three worker modules by a name read out of config.yaml at run time. A name built at run time
#   is invisible to PyInstaller, so the packaged app shipped empty folders with those names and OCR died with
#   "module 'ch_ppocr_v3_det' has no attribute 'TextDetector'" -- in the installed app only, never in a source checkout.
#   1.4.x imports those modules normally (relative imports, no sys.path games), so the packaging tool can see them --
#   but 1.4.x is only published for Python below 3.13, and on 3.13 the newest installable release is 1.2.3, the one
#   with the trick. That is exactly how it shipped: the build asked for 3.12, used whatever `py` offered first (3.13),
#   and pip quietly resolved to 1.2.3. So: take the safe version where the interpreter allows it, keep the affected
#   one working where it doesn't (installer/StudyTerminal.spec ships its real .py files so the run-time import finds
#   code instead of an empty folder), and let the packaged self-test prove whichever one ends up installed.
#   Changing either pin needs that self-test to pass inside the built .exe -- app/screen/ocr_health.py, run against
#   the installer by scripts/windows-reliability.ps1, gating the release in CI.
